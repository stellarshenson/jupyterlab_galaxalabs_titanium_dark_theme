11. **Task - Suppress Stuck Pressed Shadow** (v1.0.49): Killed ugly inset box-shadow that stuck on file browser Upload button after use<br>
    **Result**: JupyterLab core leaves the Upload toolbar button at `aria-pressed="true"` after a file upload completes - the button never resets, so the fastui `:host([aria-pressed="true"])` rule rendered a permanent `inset 0 0 2px 2px` shadow that looked broken. Theme can only hide the symptom, not reset the stuck state, so added scoped override `.jp-FileBrowser-toolbar jp-button[aria-pressed='true'] { box-shadow: none !important; }` to `style/custom.css` - overrides the shadow on the `<jp-button>` host without piercing shadow DOM, scoped to the file browser so genuine toggle buttons elsewhere keep their pressed feedback. Mirrors the Sublime theme fix. Updated `Makefile` to canonical v1.32 (project-local `.nodeenv/` instead of `nodeenv -p` which failed "Text file busy") and gitignored `.nodeenv/`.

12. **Task - Rename Visible Theme To GalaxaLabs Concrete Dark** (v1.0.49): Changed the name shown in the JupyterLab theme menu from Stellars Darcula Dark Theme to GalaxaLabs Concrete Dark Theme<br>
    **Result**: Single-line change to the `manager.register` `name` field in `src/index.ts`. **Trigger**: the theme family was rebranded under GalaxaLabs, and two light counterparts were built alongside it - `jupyterlab_galaxalabs_concrete_light_theme` (this theme's light sibling) and `jupyterlab_galaxalabs_steel_light_theme`. **Why only the display name**: the repository, the npm package `stellars_jupyterlab_darcula_theme` and the PyPI distribution keep their existing identifiers, so no installed user is broken by a package rename; only the string in Settings → Theme changes, which existing users will see rename on upgrade. No file under `ui-tests` references the old string, so the galata baselines are unaffected.
